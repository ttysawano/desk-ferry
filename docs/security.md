# Security Notes

Stage 2 adds the secure mock transport foundation. The repository must not
contain real PSKs, private keys, certificates, access tokens, or production
secrets.

Required constraints:

- Do not use plaintext TCP as the normal runtime path.
- Do not implement custom cryptography.
- Do not log key input content, text input, specific key codes, or concrete keystroke sequences.
- Keep OS-dependent APIs out of `desk-ferry-common`.

`examples/secret.psk.example` contains only a dummy placeholder.

## Stage 2 Transport

The normal runtime path is:

```text
TCP connect
  -> TLS handshake
  -> client verifies the server certificate SHA-256 fingerprint
  -> PSK challenge-response authentication
  -> hello and post-authentication protocol messages
```

TLS-PSK is not required. DeskFerry uses ordinary TLS plus application-level PSK
authentication after TLS is established.

## Server Fingerprint

The mock client requires `security.server_fingerprint` in configuration. The
fingerprint is the SHA-256 digest of the server certificate DER bytes, encoded
as hex. Colon-separated hex is accepted by the verifier.

If the fingerprint is missing or does not match the server certificate, the
client refuses the connection.

## PSK Challenge-Response

The PSK is read from a local file and is never sent over the wire.

Authentication uses:

```text
hmac = HMAC-SHA256(psk, nonce || host_name || protocol_version)
```

The nonce is generated by the server for each authentication attempt. A client
is accepted only when:

- the host name is configured and allowed by the server,
- the HMAC verifies for the current nonce,
- the protocol version matches.

Input events are rejected before authentication succeeds.

## Logging

Normal logs and protocol dump summaries may include generic message classes, but
must not include PSKs, HMAC values, key codes, text input, or concrete
keystroke sequences.
